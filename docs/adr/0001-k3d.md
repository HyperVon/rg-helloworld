# ADR-0001: k3d for the local Kubernetes cluster

- Status: Accepted
- Date: 2026-08-04

## Context

The acceptance environment must run a real Kubernetes cluster on one laptop.
Options included k3d, kind, minikube, and heavyweight multi-VM clusters.

## Decision

Use **k3d** (k3s in Docker containers) with a local Docker registry. The
cluster is created by a deterministic shell script (`scripts/k3d-create.sh`)
rather than Terraform, avoiding a provider-bootstrap circular dependency.

## Consequences

- Lightweight laptop footprint compared to multi-VM clusters.
- k3s ships its own ingress and local-path storage.
- The cluster lifecycle is script-managed; Terraform (ADR-0002 companion)
  manages everything inside the cluster.
